# FQ2 formal training-scale protocol — frozen before fit

Reviewer control `quant-ai-ml-execution-control.md` at Quant-Application commit `80cdd8009d93434764319c3725d4ddefedb97f97` reclassifies the previous 20k/15-epoch Q2–Q6 as pilot. These records remain unchanged. FQ2 changes training **capacity and optimization budget**, not the five causal features, original-event h20 target, 32-state context, time roles or evaluation rows. Every June/September/November result is retrospective because these dates were previously exposed.

The machine settings are `configs/sequence_ml_fq2_v1.json`. For each of five stocks and each 50k/100k/200k level, the existing eligibility builder selects Jan–Mar original-event endpoints with its frozen seed-7, uniform-day-quota rule. B1 history XGBoost and S0 one-layer hidden-64 GRU seeds 7/17/29 receive exactly the **same within-level train endpoint identities**, verified by a public endpoint-identity hash. Size-level selections need not be nested; each answers performance under that sample budget. April is dev. June, September and November are retrospective diagnostics, never tuning or a sealed final. Evaluation uses original-event-index stride 20 on the same eligible rows across all sizes/arms.

B1 keeps the pilot's single 300-tree XGBoost setting. GRU retains the original AdamW optimizer, learning rate, weight decay, batch size, feature/target normalization fit only on selected train endpoints and independent hidden state per window. The declared change is max **60 epochs**, patience **8**, with early stopping by April dev MSE. Seeds are 7, 17 and 29. No learning-rate, feature, threshold or architecture search uses historical evaluation outcomes. CUDA is required; a CPU fallback is not a valid formal FQ2 result. B1 may fit on CPU in the same host, while S0 must fit and infer on the allocated GPU. The reported GPU occupancy time is measured from synchronized fit and inference sections; it is allocated device wall time, not SM utilization.

At each level publish every stock/seed dev and historical IC, all defined/undefined day cells, learning curves, best epochs, training-limit flags, fit/inference time, GPU peak allocation/reservation, process peak RSS, exact data/model/prediction hashes, and failed/retried attempts. Aggregate with full denominators. The paired primary statistic is the mean of seed-specific S0 minus same-size B1 equal-stock/day IC; show each seed and all three months, with five-trading-day date-block uncertainty for fitted-model date variation. Do not treat rows or overlapping windows as independent samples. The 20k pilot is an archival reference only, not pooled with formal estimates.

If all sizes finish, carry the 200k B1 and all three 200k S0 seeds to FQ3, regardless of a favorable or unfavorable historical ΔIC. A last-epoch best model at epoch 60 remains `training_limited`; do not rebrand it as a simple-model win. Stop and checkpoint only on a genuine documented resource/correctness issue after bounded engineering repair. No résumé or PDF edits are part of FQ2.
